## Implemented

Map layers → Detail & caching → Prepare ahead checkbox; default off, stored locally as ridgeline-prepare-ahead-v1. Original only; existing fieldset disables it in Three. After the visible view settles, native raster source loading creates decoded/mipmapped GPU imagery textures. Native RasterDEM worker output remains in native Tile objects, and Terrain.getTerrainData uploads the decoded DEM into its GPU texture. Existing shared native terrain grid is reused; no extra meshes or off-screen draws are introduced. This prepares **source textures and measured elevation**, not the finished terrain colour RTT atlas. Normal image composition and finer LOD refinement still occur when the area becomes visible.

New public/prepare-ahead.js is guarded for pinned MapLibre6.14.0 and supported source/cache shapes. It uses native _addTile then _removeTile to park a single off-screen job through existing RidgeRasterResidency adapters. Native source/cached objects, reload metadata, reuse and eviction ownership are retained. Real visible selection can adopt the in-flight object; cancellation must never abort that adopted request. Cancellation removes only empty unused parked network work; an already-running native decode is allowed to finish into the cache, and no new background task starts while pending off-screen native work remains; already decoded/valid data remains cached. Failed background-only hints are identified by a WeakSet and do not contribute to app source-fallback counters or pointless visible retry timers. Once adopted into view, normal error handling applies. Source/key/grade changes clear stale plans; context loss, hiding, checkbox disable, low-power, data-saver, renderer switching and teardown stop background scheduling. Context restore can resume after the view is ready.

## Efficiency and limits

- Wait650ms; use requestIdleCallback with at least4ms idle allowance when supported, timer fallback otherwise. At most1 request/preparation task active,350ms spacing after completion. Native asynchronous imagery decode/upload stays native; cancellation aborts pending work when movement begins.
- Require map.areTilesLoaded(), no native RTT follow-up frame and no held incomplete cover. Existing tiny directional byte-only warmup is unchanged; preparation waits while byte-cache requests remain pending.
- Plan bounded neighborhoods around Mercator camera position and first-hit surface, within existing NZ bounds. At most16 candidates per source, interleaved imagery/DEM;12 tasks per settled view,24 tasks/minute. Source zoom is one below nearby loaded source detail, capped at15; no preparation at source zoom<6. Requested visible LOD/frustum policy is untouched.
- No separate cache or extra memory allowance. Require estimated source allocation below90% of each existing source budget, compressed bytes below85%, and a per-view estimate capped at min(12 MiB,8% of the combined imagery/DEM source budgets). All prepared resources remain subject to the96–700 MiB slider and normal shared cache eviction.
- Deduplicate source tiles/complete same-or-finer visible coverage; build the coverage index once per source. Skip already prepared resources. Seen/cooldown entries are bounded to256, including failures; job queue is bounded to12, history to24/minute. No GPU polling/readback, canvas resizing, hidden renderer, camera mutation, worker duplication or extra draw tiles.
- Native getTerrainData needs a representative render ID to locate the exact DEM parent. Remove only newly created representative source/uniform cache entries afterwards, preserving any existing native entries; retain the actual GPU DEM. This avoids accumulating lookup matrices for tiles that were never drawn.

Diagnostics include prepareAhead source preparation counts, reuse, cancellation, failure category and gating reason in Save imagery report. No URLs, API keys or extra location history are recorded by this module.
