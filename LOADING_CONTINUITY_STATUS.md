## Implementation and measured validation

Implemented in native-residency.js / raster-residency.js; native engine files and LOD selection modules are unchanged. DEM leases cover currently rendered and warm terrain; under memory pressure unused colour drapes are dropped before their required DEMs. Visible fallback DEMs are never discarded merely to meet an off-screen budget; protectedPressure exposes a needed-view overflow. Cache getByKey now refreshes LRU on actual fallback reads. Hidden native-cache expiry timers are suppressed; native freshness metadata/timers are restored on reuse. Errored tiles with valid textures revalidate without throwing away the old texture; empty errored tiles still retry as fresh loading tiles. Pending off-screen batches are limited to8 imagery /4 DEM (4/2 save-data), preserving room for newly visible requests.

Parent/child replacement waits for DEM and image coverage instead of dropping a valid cover after1.8s. It handles multi-level zoom jumps and complete child covers during zoom-out, with no overlapping parent/child draw list. An already-rendered complete colour atlas survives incomplete source arrivals through the actual native prepareForRender/fingerprint path. Per-render coverage is recorded only when a texture stack is painted; partial atlases remain eligible for progressive repaint and cannot be frozen as complete images. Ownership follows each Tile.rttObjects array so a released/reallocated atlas cannot inherit stale completeness. Style/layer/revision changes remain authoritative.
