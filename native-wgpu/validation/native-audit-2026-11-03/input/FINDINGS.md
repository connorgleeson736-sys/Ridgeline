# Ridgeline native Android latency audit
## Scope

Audited the Kotlin/SurfaceView and Rust/wgpu application on `native-renderer-performance`. The branch head was `e2741ae4403a484b9dadf17d9d096b75c8f2bbd2`. The release record identifies `d258866d31509174c01aa0022094015d687566c2` as the source for **0.1.9 UI and Layers Base**, version code 10. Comparing the two commits showed release documentation, checkpoint and validation changes. The application code was the same. I checked source and release metadata and ran standalone experiments, without running the APK on a handset. [Release record](https://github.com/connorgleeson736-sys/Ridgeline/blob/e2741ae4403a484b9dadf17d9d096b75c8f2bbd2/native-wgpu/validation/ui-layers-2026-11-01/release.json) · [Checkpoint](https://github.com/connorgleeson736-sys/Ridgeline/blob/e2741ae4403a484b9dadf17d9d096b75c8f2bbd2/native-wgpu/checkpoints/README.md)

The native transport already separates network admission from decode, caps background transfers, deduplicates shared inputs, and accepts prepared uploads only after JNI acknowledgement. Several bottlenecks discussed in the older 0.1.5 audit were fixed by 0.1.7 and 0.1.8. The numerical results below come from new, focused experiments. [Native release history](https://github.com/connorgleeson736-sys/Ridgeline/blob/e2741ae4403a484b9dadf17d9d096b75c8f2bbd2/native-wgpu/README.md)

## 1. Let the main DEM tile reveal the measured interior immediately

**Latency metric** — time from entering new 3D coverage to seeing full-detail terrain around the centre of the screen.

The production geometry worker usually samples a 129 × 129 grid from a 256 × 256 elevation raster one zoom level lower. Each geometry tile occupies one quadrant of that raster. Bilinear sampling along the two outside edges reaches into neighbouring rasters. For a normal inland tile this creates a footprint of four source rasters. Most tasks wait on all input futures. The prioritised focus pipeline already decodes available inputs early, but it still yields while any required input remains outstanding. Geometry is offered to the renderer only after the complete grid and its error profile are ready. [Sampling and footprint](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/android/app/src/main/java/nz/ridgeline/nativeapp/DemSampling.kt#L37-L99) · [Focus pipeline](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/android/app/src/main/java/nz/ridgeline/nativeapp/GeometryInputPipeline.kt#L13-L26) · [Worker and upload path](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/android/app/src/main/java/nz/ridgeline/nativeapp/TileLoader.kt#L522-L562)

**What one source already determines.** If the main raster is decoded and finite but all three neighbours are missing, only one outside vertex row and one outside column are unavailable. That leaves 128 × 128 exact heights and **127 × 127 = 16,129 drawable cells out of 16,384**. The other **255 cells** form an L-shaped rim. This 98.44% is a fraction of the patch's cells. Perspective, camera position and occlusion determine its fraction of the screen.

**Experiments.** A port of the branch's pixel-centre sampling math checked all four quadrant orientations at geometry zooms 8, 12, 16 and 19 over deterministic finite source data. Every available height matched the complete-grid reference bit for bit in Float32, for 262,144 comparisons. An independent surfaceless OpenGL ES 3.2 fixture rendered an oblique synthetic heightfield using the branch's full-grid triangle diagonal. For each quadrant it compared a single full draw against an interior draw followed by the 255-cell rim. All four completed 640 × 512 frames matched in every RGBA pixel. The missing rim was visible in each intermediate image. This exercises geometry ownership and depth in a standalone shader. It does not exercise the Android production shader, parent stitching, adaptive LOD or real network timing.

**Implementation.** Start with a feature-flagged path for one high-priority patch under the focus, restricted to source zoom delta one, a valid main raster, ready imagery or a usable image ancestor, and measured fallback geometry for the rim. Retain the already-drawn parent on the missing strip only. The existing geographic cover partitions quadtree regions, so it needs an explicit cell-rectangle representation or a dedicated transition pass to represent this strip cleanly. Give the temporary patch its own readiness state, separate from a complete GPU acknowledgement. Use existing exact grid indices for the valid rectangle. Never feed absent heights into culling, route draping, picking, camera clearance or error profiling. Map those consumers to the same displayed owner. On completion atomically promote the final seam-safe patch and release the parent strip. Preserve cancellation, source freshness, DEM no-data repair, exaggeration and memory limits. Keep the complete-patch path for unsupported cases. [Cover construction](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/core/src/surface.rs) · [Native upload short-circuit by resident tile ID](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/renderer/src/android.rs#L641-L687) · [Geometry acceptance](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/renderer/src/lib.rs#L672-L790)

**Latency expectation.** If an edge donor becomes usable 300 ms after the centre raster, up to roughly 300 ms of dependency wait is available to remove for the interior. Subtract scheduling and presentation costs and any time still spent waiting for imagery. When all four sources are already warm there may be no gain, so avoid staging two uploads in that case. Measure the gap between centre-raster readiness and last required donor before expanding rollout.

## 2. Remove the render-thread round trip from the first drag movement

**Latency metric** — time from the first actionable drag delta to the first submitted and then presented frame with a changed camera.

`beginGesture` computes a provisional camera-plane anchor, sets `anchorPending` and posts terrain picking to the GPU handler. `applyGesture` immediately returns while the flag is set. A callback from the handler back to the UI thread clears it and applies accumulated motion. The sequence repeats for a change in pointer count. The pick itself intersects CPU heightfields under the renderer-state mutex. It shares a handler with tile uploads, overlay replacement and acquisition/presentation of surface frames. A slow frame can therefore hold up acceptance of the next camera pose. [Gesture path](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/android/app/src/main/java/nz/ridgeline/nativeapp/TerrainView.kt#L446-L478) · [Pointer transitions](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/android/app/src/main/java/nz/ridgeline/nativeapp/TerrainView.kt#L539-L569) · [CPU pick](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/renderer/src/lib.rs#L1306-L1414)

**Implementation.** Publish an immutable picking snapshot for the last submitted scene. Include the camera, viewport, actually drawable coverage, heightfield references, relief and generation. An input worker can compute the exact anchor during the interval between finger-down and exceeding touch slop, without joining the render handler's queue. Keep only the latest relevant gesture and safely release old heightfield references. For an implementation that also allows provisional motion when a pick arrives late, re-anchor at the current pointer and displayed pose, and discard stale generation results. Validate the maximum screen-space drift over steep ridges. A provisional movement policy changes first-touch behaviour when the approximate and true surfaces differ. Keep route edits and waypoint placement exact.

**A second source of delay before the draw.** The upload budget allows the first pending tile upload even if the computed allowance is zero, subject to its byte/backlog checks. Replacing map line data or a whole label atlas takes place outside that tile-upload budget and before the latest camera pose is read. Give a newly moved camera priority over optional uploads when a complete cover exists. Reserve a bounded later opportunity for uploads so imagery still refines under sustained gestures. Retain uploads required to establish initial coverage. [Upload admission](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/android/app/src/main/java/nz/ridgeline/nativeapp/UploadAdmission.kt#L4-L16) · [Frame sequence](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/android/app/src/main/java/nz/ridgeline/nativeapp/TerrainView.kt#L171-L251)

The gate is present in source. Its actual contribution depends on whether the pick has already returned when the finger starts to move, and whether the render handler is otherwise free to submit. Measure event time, pick enqueue/start/finish, camera change, and presentation. JNI render return alone cannot establish input-to-display latency.

## 3. Cut repeated overlay work without changing the visible lines

The LINZ imagery boundary is enabled by default. Whenever a changed layer batch is published at zoom 8 or above on that basemap, the layer worker loops over every selected tile and every national boundary path. It clips every segment even where the entire path is outside the box. This uses the same single worker as vector tile processing. [Defaults](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/android/app/src/main/java/nz/ridgeline/nativeapp/MapSettings.kt#L5-L14) · [Publication and clipping](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/android/app/src/main/java/nz/ridgeline/nativeapp/MapLayers.kt#L76-L123)

I ran a direct Node port of the clipping routine on the exact shipped GeoJSON, which contains **253 paths and 10,660 segments**. Each fixture uses a 6 × 4 tile rectangle centred near Aoraki at a single zoom. The prototype precomputes tight bounding boxes per path and per 32-segment chunk and runs the same clipper for surviving segments. It preserves path order, clipping arithmetic and fragment breaks. Every output coordinate and ordered fragment matched the baseline across all 72 tile boxes.

| Zoom | Segment tests before | Segment tests after | Output line fragments | Median host time before | After |
| --- | ---: | ---: | ---: | ---: | ---: |
| 10 | 255,840 | 2,658 | 18 | 5.937 ms | 0.308 ms |
| 12 | 255,840 | 1,248 | 16 | 5.895 ms | 0.294 ms |
| 14 | 255,840 | 736 | 11 | 5.839 ms | 0.226 ms |

These are clipping-only times for a host port, not handset frame times. Precompute the index once and cache immutable clipped boundary fragments by asset revision and canonical tile ID. The worker can then reuse the clipped lines when only a vector tile or label priority changes.

**On the render thread, isolate route edits.** Changing a waypoint sets `route_dirty`. During render, that flag also marks cartography, labels and inspection dirty. Rebuilding cartography walks line segments against the terrain cover, drapes the intersections, and uploads the line buffer. A route-only change can repeat that work with unchanged roads, tracks and terrain. Use separate route and terrain-surface revisions. On terrain changes, invalidate only draped fragments backed by changed coverage or heights; relief and mode changes must still invalidate dependent geometry. On a route-only change, refresh the route and any genuinely affected adaptive or inspection state. [Route mutation](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/renderer/src/routes.rs#L220-L225) · [Invalidation before draw](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/renderer/src/lib.rs#L1425-L1444) · [Draping and upload](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/renderer/src/cartography.rs#L17-L89)

**Decouple label priority from texture content.** A changed ordered candidate list can rebuild the entire native font atlas, including when the same labels merely change distance order. The 2048-wide RGBA atlas can reach 16 MiB; that is its upper bound. The render handler uploads it before sampling the camera pose. Keep stable slots for text/style sprites and separate placement/priority metadata. Update dirty texture regions, retain the previous atlas until its replacement and mapping are ready, and skip re-parsing the same line packet when only labels changed. [Layer publication](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/android/app/src/main/java/nz/ridgeline/nativeapp/MapLayers.kt#L93-L104) · [Atlas construction](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/android/app/src/main/java/nz/ridgeline/nativeapp/NativeLabels.kt#L17-L54) · [GPU upload](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/renderer/src/labels.rs#L113-L147)

## 4. Give unshaded 2D a planar rendering path

The 0.1.9 app already skips elevation downloads in unshaded 2D. A geometry cache miss still allocates a 66,564-byte zero height buffer for each tile and follows normal geometry upload. A full unshaded patch with no exact-route requirement uses step four, or **2,680 surface triangles** before skirts. A planar rectangle needs **two**. [2D geometry preparation](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/android/app/src/main/java/nz/ridgeline/nativeapp/TileLoader.kt#L522-L525) · [Step selection](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/renderer/src/adaptive.rs#L20-L33) · [Triangle count](https://github.com/connorgleeson736-sys/Ridgeline/blob/d258866d31509174c01aa0022094015d687566c2/native-wgpu/core/src/adaptive.rs#L160-L174)

Start by sharing the zero field and decoupling planar imagery from per-tile geometry upload. That can remove allocation and readiness gates while preserving the current rasterisation. A dedicated planar shader can then draw the same clipped image region as two triangles. Preserve the image fallback footprint, nearest-mip Topo sampling, depth-tested overlays, planar picking, and the transition back to 3D. Keep real DEMs for shaded 2D when required.

**Pixel check found a real qualification.** The GLES fixture rendered a high-frequency 256 × 256 texture with nearest-texel addressing at two camera offsets. Geometry coverage matched at every pixel. The subpixel-offset case matched every colour. In the aligned case, 1,950 of 184,320 covered pixels sampled a different texel across the two triangulations. Both draws sampled the same input image. Resolve the tie convention and check real Topo text, rotated views and tile edges before treating the quad as a visual match. The triangle count alone cannot predict phone frame time.

## Order and device acceptance

1. Instrument first drag and first sharp terrain separately on 0.1.9. Replay a warm drag with data resident, then a pan into newly requested terrain with the same view, settings and phone temperature.
2. Land the boundary index and route-only invalidation separately. They are low-risk, measurable, and preserve existing detail.
3. A/B the gesture snapshot and camera-first frame path under a streaming backlog. Compare p50/p95 first-move-to-present and sustained p95 frame intervals. Include quick reversals, pinch, steep slopes and context recreation.
4. Gate progressive terrain to the focus patch. Compare actual centre-ray quality and time to the first frame with exact target terrain under the crosshair. Count extra bytes, admissions and GPU work. Check parent/child borders with a missing neighbour, no-data repairs, cache eviction, and rapid camera or detail changes. A typical distribution of centre-to-halo delays is necessary for an overall estimate.

## Reproduce

Run the JavaScript checks with Node 20 or newer from the root of the specified Ridgeline checkout. The graphics fixture requires a Linux surfaceless EGL/GLES implementation and a C++17 compiler; it can run separately. The terrain and boundary checks are ports, and the draw fixture is a standalone graphics proof.

```sh
node /path/to/check-halo.mjs
node /path/to/check-boundary.mjs
g++ -O2 -std=c++17 /path/to/check-split-draw.cpp -o /tmp/ridge-split -l:libEGL.so.1 -l:libGL.so.1
EGL_PLATFORM=surfaceless /tmp/ridge-split
```
