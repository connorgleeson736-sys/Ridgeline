## Exact restart procedure

1. Open the SAME Site through Sites' source helper, obtain latest remote source;
   do not use the old `/workspace/sites/ridgeline-nz` snapshot or create a new Site.
2. Install Python3.12+ venv with `CXX=g++ CC=gcc pip install -r
   tools/lidar_pipeline/requirements.txt`. Default clang++ is unavailable here.
3. Run `python -m tools.lidar_pipeline.build_native --directory <native-dir>`.
   Pinned official Debian headers/static libraries; no root/apt system changes.
4. Get Site service access. Start `python -m tools.lidar_pipeline.runner` with
   terminal echo disabled and send ONE hidden-stdin JSON object containing
   `base`, ephemeral `token`, new absolute `root`, `operation:"restore"`, and the
   exact `run` above. Optional `only:[task names]`. Never persist/expose tokens.
   Restore enumerates/hash-validates immutable journals and all artifacts,
   resumes ranged downloads, and writes task commit markers last.
5. Run `operation:"sync"` with fresh service access to finish staged uploads;
   then `partition`, `local-trial` with `tiles`/`native_dir`, `seams` with matching
   `tiles`/`local_delta`, `certified-lod` with `tiles`/`budget`/`delta`, or `orient`
   with root-relative `source`, safe `label`, and `native_dir`; `codec` uses `source`/`label`. Inspect pending
   plan tasks and artifacts; checksum-valid generations resume automatically.
6. Commit/push source working milestones through the Sites helper; save/deploy
   private versions and verify terminal success. Mirror status to external Doc.
   Preserve owner-only audience and original viewer fallback. Do not call complete
