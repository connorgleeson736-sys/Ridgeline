## Changes

Devices reporting 4 GB RAM now use the existing standard-device cache profile by default. At the default Keep loaded views setting, the six budgets sum to **352 MiB**: imagery source textures128; decoded elevation48; warm rendered views96; spare unused rendering targets16; compressed imagery48; compressed elevation16. Devices below4 GB retain188 MiB. Save-data on4 GB retains reduced168 MiB. These are estimated cache budgets, excluding visible geometry/textures, route/profile caches, runtime/worker overhead and transient allocations; not a total browser/GPU memory cap. Required visible fallback DEMs can exceed their off-screen target rather than disappear. Existing user-selected view-cache values32–256 continue to apply. Legacy automatically saved48 upgrades to96 once using cacheProfile2; subsequent manual48 and other custom choices persist. No DEM values, geometry resolution, native LOD policy, imagery pixels/grade or native engine changes.

Eliminate eager imageReadiness construction during every native RTT preparation: a per-call lazy scope computes a coverage snapshot only if a transition actually needs it. Scope cannot survive native update/prepare boundaries, so asynchronous source changes cannot reuse stale coverage. Keep render-completion ownership/completeness checks and source/style revision invalidation. With an unchanged render set and no held transition, skip our additional transition search; native updates/rendering and source lifecycle still run. During transitions, memoize DEM/usable lookups, index warm descendant covers by desired ancestors, and use set membership for draw-list comparison. Parent/child readiness, full child coverage, delayed source arrival, crack/zero-DEM protection and context recovery remain tested.

Source residency trim returns immediately below the byte budget instead of walking every visible/warm DEM dependency per cache insertion. Under pressure, original protected-DEM checks and coupled warm-drape relief still run. Pending-work scans short circuit without allocating filtered arrays. Reduce parked *unfinished, empty* off-screen requests from8→4 imagery and4→2 DEM (save-data4→2 and2→1) so obsolete downloads contend less with newly visible work. Already valid loaded textures/DEMs remain cached; revalidation retains valid coverage. Native parallel image request limit stays12, save-data6. No extra speculative tiles or network concurrency increase.

Predictive byte-cache warmups no longer clone buffers that nobody consumes. A visible subscriber sharing that pending request still receives its own independently transferable buffer; cached originals remain isolated from consumer mutation. Compressed-cache diagnostics now report budgets. Passive navigation render intervals are retained in a240-value ring and summarized only on Download imagery report (p50/p95/max); no GPU readbacks, polling, extra repaint or network requests.
